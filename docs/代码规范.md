# 代码规范

> 适用范围：`apps/api`、`apps/web-next`、`apps/mobile`。`apps/web`（Vue 端）暂不强制，但它直连 Supabase 的写法不在本规范推荐范围内。
>
> 本文只约定「文件怎么分、每层能干什么」。格式类约定沿用各 app 自己的配置（`apps/api/.prettierrc` + `oxlint.json`），不做跨端统一。

---

## 0. 一句话总则

**一个业务概念 = 后端 5 个文件 + 前端 3 层。**

- 后端：`module` / `controller` / `service` / `mapper` / `dto`，五个文件各管一件事，**prisma 只出现在 service**。
- 前端：视图层 / 数据层 / 接口层，**`snake_case` 不许越过接口层**。

判断代码该放哪，只问一句：**这段逻辑，换掉数据库或换掉 UI 之后还成立吗？** 成立的是业务（service / domain），不成立的是适配（controller / 接口层）。

---

## 1. 后端（apps/api）

### 1.1 模块目录固定五件套

以 `task` 为例：

```
apps/api/src/tasks/
├── tasks.module.ts        # 装配：controller + service
├── tasks.controller.ts    # 路由：URL、方法、参数绑定
├── tasks.service.ts       # 业务规则 + 数据库读写（this.prisma）
├── task.mapper.ts         # 字段适配：dto → Prisma data、row → 响应
└── dto/
    └── task.dto.ts        # 入参校验与类型
```

- 目录名用**复数资源名**（`tasks`、`habits`、`summaries`）；`module` / `controller` / `service` 与目录同名，`mapper` / `dto` 用**单数资源名**。
- 文件名 kebab-case，类名 PascalCase（`tasks.controller.ts` → `TasksController`）。
- DTO 统一放 `dto/` 子目录，一个模块一个 DTO 文件；一个模块下有多个子资源时才拆（如 `direction/dto/direction.dto.ts` 涵盖 goal / month / day / category）。
- 一个模块下资源超一个时，按资源拆多组 controller + service + mapper，但仍共用**一个 module 目录**（见 `direction/`：4 组 + 1 个 module，mapper 收到 `direction/mappers/`）。
- 不跨模块共用 mapper：两个模块都要的形状说明它该下移到 `common/`。

### 1.2 各层职责与红线

| 文件 | 只做 | 明令禁止 |
|------|------|----------|
| `*.controller.ts` | 声明路由与方法、绑定 `@Body/@Query/@UuidParam/@CurrentUserId`、调 service、直接 `return` | 写 `this.prisma`、写 if/else 业务判断、手动 `new Date()`、`try/catch` 后自己拼响应、import `Prisma` 类型 |
| `*.service.ts` | 业务规则、所有数据库读写、抛 `HttpException` | 出现 `@Req/@Res/Request/Response`、`setGlobalPrefix` 之类的 HTTP 细节、做字段格式转换、返回未序列化的 `Date` |
| `*.mapper.ts` | `dto → Prisma data`、`row → 响应`、声明式 serializer | 查库、抛业务异常、依赖 `userId` 之外的请求上下文 |
| `dto/*.dto.ts` | `class-validator` 装饰器 + 类型声明 | 查库、调用 service、做业务计算 |
| `*.module.ts` | `controllers` / `providers` 装配 | 写逻辑 |

**具体约定：**

1. **service 方法签名第一个参数永远是 `userId`。**
   ```ts
   list(userId: string, query: ListTaskQueryDto)
   update(userId: string, id: string, dto: UpdateTaskDto)
   ```
   线上库的 `user_id` 原本靠 Supabase RLS 兜底，自托管后必须在应用层显式过滤，**每个查询的 `where` 都要带 `user_id`**。

2. **改 / 删用单查询校验归属，不要「先查一遍再改」。**
   Prisma 的 unique where 允许附加标量条件，把 `user_id` 一起塞进去即可：
   ```ts
   async update(userId: string, id: string, dto: UpdateTaskDto) {
     const row = await this.prisma.task.update({
       where: { id, user_id: userId }, // 命中不到 → P2025 → 全局过滤器转 404
       data: toUpdateData(dto),
     });
     return taskSerializer.one(row);
   }
   ```
   为什么这样更好：少一次查询、没有「查完到改之间被别人删掉」的竞态、service 里不用再写 404 文案。
   详情查询同理用 `findUniqueOrThrow({ where: { id, user_id } })`。
   需要中文文案的地方由 `common/http/api-exception.filter.ts` 的 `MODEL_LABEL` 统一提供。

3. **字段映射只写在 mapper，用 `compact` + 三态转换函数，不要写 if 链。**
   ```ts
   export function toUpdateData(dto: UpdateTaskDto): Prisma.taskUpdateInput {
     return compact({
       title: dto.title,                      // undefined 会被丢掉
       completed: dto.completed,
       start_time: toTimestamp(dto.start_time), // undefined 保持 undefined、null 保持 null
     });
   }
   ```
   - `compact` 只丢 `undefined`、保留 `null`，对应「不改」与「清空」两种语义。
   - 时间字段一律用 `common/time/columns.ts` 的转换函数（`toDateColumn` / `toTimeColumn` / `toTimestamp` / `toLocalStart`），**禁止在业务代码里直接 `new Date(string)`**，否则 date / time / timestamptz 三种列迟早混。
   - 关系字段用 `relation(id)`：`undefined` 不动、`null` disconnect、有值 connect。

4. **出参必须序列化，且用实体内声明的 serializer。**
   Prisma 的 `date` / `time` 列是 `Date` 对象，直接返回会变成 `2026-10-29T00:00:00.000Z`，与前端历史约定不一致：
   ```ts
   export const taskSerializer = defineSerializer({ time: ['task_time'] }); // 声明哪些列是 time
   taskSerializer.one(row);
   taskSerializer.many(rows);
   ```
   - `date` 列 → `YYYY-MM-DD`（按 UTC 取值）
   - `time` 列 → `HH:mm:ss`
   - `localDate` → 按进程时区取 `YYYY-MM-DD`（本地零点写入的 timestamptz，如 `period_start`）
   - `json` → 对象，空值归一成 `{}`
   - 未声明的 `Date` → ISO 字符串
   - `pick` 用于树形结构只输出必要字段；`fallback` 用于 `updated_at` 回落到 `created_at`
   嵌套结构逐层调用各自的 serializer，**不要整行 `JSON.stringify`**——嵌套里的时间列不会被处理。

5. **错误只用 Nest 内置异常**（`NotFoundException` / `BadRequestException` / `ForbiddenException`），文案面向用户、中文、不带技术细节。不要自定义错误码体系，也不要返回 `{ code, msg }` 包装。

6. **ESM 的 import 必须带 `.js` 后缀**（`import { PrismaService } from '../prisma/prisma.service.js'`），漏了会在 `node dist/main` 时炸。

### 1.3 方法命名固定词汇

| 场景 | 命名 |
|------|------|
| 列表 | `list`（带筛选）、`listInbox` / `listByKind`（特定子集） |
| 详情 | `getById` |
| 创建 / 更新 / 删除 | `create` / `update` / `remove` |
| 特殊动作 | 动词短语：`toggle`、`batchUpsert`、`carryOver` |

### 1.4 模块之间

- service 之间**允许**注入复用（`DirectionModule` 里 goals ↔ goal-months），但**禁止循环依赖**；一旦要互相注入，说明该抽第三层或把公共逻辑下移到 `common/`。
- 跨模块共用的纯函数（日期区间、序列化、用户解析）统一放 `src/common/`，并在 `common/index.ts` 里 re-export。
- `x-user-id` 的读取只允许出现在 `common/decorators/current-user-id.decorator.ts`，业务代码一律用 `@CurrentUserId()`，将来换 JWT 只改一处。

### 1.5 全局件（`setup-app.ts` 装配）

| 全局件 | 位置 | 职责 |
|--------|------|------|
| `ValidationPipe` | `setup-app.ts` | `whitelist` + `forbidNonWhitelisted`：未声明字段直接 400，拼错字段名不再被静默丢弃 |
| `ApiExceptionFilter` | `common/http/` | `HttpException` 原样透出；Prisma `P2002/P2003/P2025/P2023` 翻成 4xx 并按模型名生成中文文案；其余 → 500，堆栈只进日志 |
| `RequestLogInterceptor` | `common/http/` | 一行一条访问日志（方法 / 路径 / 状态 / 耗时 / 调用者），`NODE_ENV=test` 时静默 |
| `UuidParam` | `common/decorators/` | `:id` 参数在边界校验，非法 UUID 返回 400 而不是漏到 SQL 层变 500 |

**规则：不要在 service 里写 `try/catch` 去翻译数据库错误。** 需要新增一种错误语义时，只改过滤器里的 `PRISMA_STATUS` / `MODEL_LABEL` 两张表。

## 2. 前端（apps/web-next + apps/mobile）

前端是**三层 + 一个可选纯逻辑区**，不是四层。

| 层 | mobile | web-next | 只做 | 明令禁止 |
|----|--------|----------|------|----------|
| **视图层** | `app/(app)/*.tsx`<br>`src/features/*/screens/*.tsx`<br>`src/features/*/components/*.tsx` | `src/app/*/page.tsx`<br>`src/components/*` | JSX、布局、样式、把用户操作转成回调 | `fetch`、拼 URL、写 `snake_case` 字段名、做字段映射 |
| **数据层** | `src/features/*/hooks/use*.ts` | 页面内 hook + `src/lib/use-async-data.ts` | `useQuery` / `useMutation`、`queryKey`、成功后失效缓存、把接口数据整理成页面要的形状 | 拼 URL、认识后端字段名、直接操作 DOM / RN 组件 |
| **接口层** | `src/services/api/*.ts` | `src/lib/api/*.ts` | URL、method、body、**snake_case ↔ camelCase 映射**、错误转义 | 业务判断、React state / hooks、组件相关逻辑 |
| **纯逻辑区**（可选，不算层） | `src/domain/**` | `src/lib/*.ts`（`date.ts`、`goal-progress.ts`…） | 纯函数：日期、进度、分组、表单校验、排序。输入输出都是领域模型 | `fetch`、hooks、任何副作用 |

### 2.1 三条硬规则

1. **`snake_case` 不许越过接口层。** 后端的 `start_time` 在接口层就被映射成 `startAt`，组件和 domain 里永远见不到下划线字段名。
   ```ts
   // services/api/tasks.ts —— 唯一认识后端字段的地方
   type TaskRow = { id: string; title: string; start_time: string | null; end_time: string | null }
   function mapRow(row: TaskRow): TaskRecord {
     return { id: row.id, title: row.title, startAt: row.start_time, endAt: row.end_time }
   }
   ```

2. **接口层只导出「动词 + 资源」的函数，且返回领域模型，不返回后端 row。**
   ```ts
   export async function listTasksForDate(date: Date): Promise<TaskRecord[]>
   export async function createTask(input: TaskFormInput): Promise<TaskRecord>
   ```
   不许导出 `get('/tasks')` 这种通用请求器给页面用——`apiRequest` 只在接口层内部可见。

3. **错误只由接口层转一次。** `client.ts` 把非 2xx / 超时 / 连不上统一成 `ApiError`，页面和 hook 只读 `error.message`，**不再二次包装、不再拼文案**。

### 2.2 缓存与命名

- `queryKey` 用 `[资源, 维度]` 数组：`['day-tasks', dateKey]`、`['day-daily-plans', dateKey]`、`['habits']`。
- 写操作成功后**只失效相关 key**，不 `invalidateQueries()` 全量刷。
- 新增资源时，`queryKey` 的第一个元素统一用 **kebab-case 资源名**，避免同一个接口出现两种 key。

### 2.3 两端对齐

- 同一个后端接口，mobile 和 web-next 各有一份接口层文件，**映射规则必须一致**（字段名、`null → ''` 之类的兜底都要一致）。改动其中一份时，另一份同步改。
- 领域模型类型（`TaskRecord` / `HabitRecord` …）两端保持同名字段，为将来抽 `packages/shared` 做准备。目前不抽包，但**不允许两端字段名不同**。
- `web-next/src/lib/api/index.ts` 目前是单文件聚合，**超过约 400 行就按资源拆**成 `lib/api/tasks.ts` 等，与 mobile 的目录形状对齐。

## 3. 跨端契约

| 类型 | 后端产出 | 前端形态 |
|------|----------|----------|
| `date` 列 | `"2026-10-29"` | 字符串日期 key，用 `toDateKey` 比较 |
| `time` 列 | `"09:00:00"` | 字符串，展示前格式化 |
| 时间戳 | ISO 字符串 | 需要 Date 时在纯逻辑区转 |
| 用户标识 | `x-user-id` 请求头 | mobile 从 session 取，web-next 用 `DEV_USER_ID` |

**接口字段格式一旦定下不随意改。** 要改就必须三端同批改，否则会出现「web 正常、mobile 显示差一天」这类问题时无法定位。

## 5. 存量代码现状（2026-11-04 重构后）

`tasks`、`habits`、`summaries`、`daily-reports`、`direction` 五个模块已按本文对齐，不需要再重构。这次重构解决掉的历史问题：

| 历史问题 | 现在的做法 |
|----------|-----------|
| 6 个模块各写一遍 `if (dto.x !== undefined)` 映射链 | 统一 `compact()` + 三态转换函数（`toTimestamp` / `toDateColumn` / `toTimeColumn` / `toLocalStartOrNull`） |
| 序列化按「字段名」全局猜类型（叫 `day` 就当 date 列） | 每个实体在 `*.mapper.ts` 声明 `defineSerializer` spec，类型写在实体旁边 |
| 嵌套结构手写 45 行 map，漏字段不报错 | 逐层调用各层 serializer，`pick` 声明输出白名单 |
| 改 / 删前 `getById` 再 `update`，两次查询 + 竞态 | `where: { id, user_id }` 单查询，P2025 由全局过滤器转 404 |
| 非法 UUID 进到 SQL 层变 500 | `@UuidParam()` 在边界返回 400 |
| Prisma 错误原样冒泡成 500 | `ApiExceptionFilter` 按错误码翻 4xx，文案按模型名生成 |
| 拼错字段名被静默丢弃 | `forbidNonWhitelisted` 直接 400 并指出字段名 |
| 无访问日志 | `RequestLogInterceptor` 一行一条 |
| 结转规则混在 service 循环里 | 抽成纯函数 `direction/goal-day.carry-over.ts`，有独立单测 |

**新代码一律按本文执行**。发现存量偏离本文的地方，改到哪个模块顺手对齐，不做无关重构。

每一层有一份独立的操作手册，放在 `.workbuddy/skills/`，按文件类型自动命中。写代码前先看对应那份，里面有可直接抄的骨架和该层的红线清单。

| Skill | 命中场景 | 对应本文 |
|-------|----------|----------|
| `api-controller` | 改 `*.controller.ts`、加路由、调接口路径 | §1.2 |
| `api-service` | 改 `*.service.ts`、写查询、加归属校验 | §1.2 |
| `api-dto` | 改 `dto/*.dto.ts`、加校验、字段被静默丢弃 | §1.2 |
| `api-module` | 新增模块、接口 404、`Nest can't resolve dependencies` | §1.2 / §1.4 |

| `web-domain` | 改 `domain/`、`lib/*.ts`、日期与进度计算 | §2 |
