# monorepo 迁移计划

> 日期：2026-10-24
> 状态：执行中（阶段 1 已完成，等待提交点 A）
> 关联仓库：`rhythm`（桌面端，本仓库）、`rhythm-mobile`（移动端，`../rhythm-mobile`）

---

## 1. 背景与目标

桌面端（Vue 3 + Vite）与移动端（Expo + React Native）目前是两个独立仓库，各自维护依赖与配置。合并为 pnpm monorepo，实现：

- 统一的依赖管理与 lockfile
- 后续可抽取共享代码到 `packages/`（两端已共同依赖 `@supabase/supabase-js`、`clsx`、`tailwind-merge`、`class-variance-authority`）
- 单一仓库内同步开发、同步提交

## 2. 现状盘点（2026-10-24 已确认）

| 项 | 桌面端 `rhythm` | 移动端 `rhythm-mobile` |
|----|----------------|----------------------|
| 远程 | `github.com/sui-hua/rhythm` | `github.com/sui-hua/rhythm-mobile` |
| 与 origin 差异 | 无（已同步） | 无（已快进同步，42f7a9d → 3a8187a） |
| 包管理器 | bun（`bun.lock`，被 git 跟踪） | pnpm（`pnpm-lock.yaml`，`packageManager: pnpm@10.33.0`） |
| 工作区 | 有 2 个未提交文件（见阶段 0） | 干净 |
| CI 配置 | 无 `.github` | 无 |
| 特别注意 | 根目录残留未跟踪的旧 `pnpm-lock.yaml` | `.env` 被 git 跟踪（需取消跟踪） |

## 3. 方案决策

| 决策点 | 结论 | 理由 |
|--------|------|------|
| monorepo 根仓库 | 现有 `rhythm` 仓库 | 更活跃；保留全部历史；免去新建仓库的 remote/issue 迁移 |
| 包管理器 | **pnpm workspaces** | 移动端刚从 bun 迁到 pnpm（Expo 兼容性）；pnpm workspaces 是 Expo 官方 monorepo 方案；根 AGENTS.md 本按 pnpm 编写 |
| 移动端历史 | `git subtree add` 合并 | 保留 `rhythm-mobile` 全部提交历史，文件直接落入 `apps/mobile`，与 web 端零冲突 |
| 目录布局 | `apps/web` + `apps/mobile` + `packages/`（预留） | 社区标准布局 |

### 阶段 2：subtree 合并移动端（代理，保留历史）

前置：工作区干净（commit A 已落）。

```bash
git remote add mobile ../rhythm-mobile
git fetch mobile
git subtree add --prefix=apps/mobile mobile/main \
  --message "chore(mobile): 以 subtree 方式合入 rhythm-mobile"
git remote remove mobile
```

自动生成一个 merge commit（`git subtree` 命令的一部分，非手工 commit）。之后 `git log apps/mobile/` 可追溯移动端全部历史。

**合并后立即处理 `.env`**（移动端历史上跟踪了 `.env`）：

```bash
git rm --cached apps/mobile/.env
```

根 `.gitignore` 的 `.env` 规则（无路径锚定）会自动匹配子目录，取消跟踪后即被忽略。同时在 `apps/mobile/.gitignore` 追加一行 `.env` 作为双保险。

### 阶段 3：workspace 配置适配（代理）

| 文件 | 改动 |
|------|------|
| `apps/web/package.json` | `name` → `@rhythm/web`（其余不动） |
| `apps/mobile/package.json` | `name` → `@rhythm/mobile`；删除 `packageManager` 字段（根统一声明） |

`apps/mobile/metro.config.js` 改为：

```js
const { getDefaultConfig } = require('expo/metro-config')
const path = require('path')

const projectRoot = __dirname
// monorepo 根，包含提升后的公共依赖
const workspaceRoot = path.resolve(projectRoot, '../..')

const config = getDefaultConfig(projectRoot)
// 监听 workspace 根目录的依赖变化
config.watchFolders = [workspaceRoot]
// 让 Metro 同时在包内与根 node_modules 解析模块
config.resolver.nodeModulesPaths = [
  path.resolve(projectRoot, 'node_modules'),
  path.resolve(workspaceRoot, 'node_modules'),
]

module.exports = config
```

## 7. 影响范围与风险

| 风险 | 说明 | 缓解 |
|------|------|------|
| Metro 无法解析依赖 | pnpm 符号链接结构与 Metro 不兼容 | `.npmrc` 设 `node-linker=hoisted` + metro.config.js 加 watchFolders（Expo 官方方案） |
| Vercel 首次部署失败 | push 后路径变化，Vercel 仍按根目录构建 | 阶段 6 先改 Root Directory 再 push |
| `.env` 泄漏进历史 | 移动端 `.env` 已在 git 历史中（密钥为 Supabase anon key，本为客户端公开值，风险低） | 取消跟踪即可；如介意可后续 rotate key |
| 路径类工具失效 | IDE 工作区、e2e 报告路径等基于根目录的配置 | `apps/web/.gitignore` 承接路径条目；IDE 改开 monorepo 根 |
| subtree 操作失误 | merge commit 难以撤销 | 阶段间有独立 commit 作为回滚点；全程未 push |

**回滚方案**：每个阶段一个 commit，任一阶段失败 `git reset --hard <上一 commit>` 即可；阶段 2 的 merge commit 同样可 reset。原 `rhythm-mobile` 仓库在其本地目录与 GitHub 上完好无损，不受影响。
