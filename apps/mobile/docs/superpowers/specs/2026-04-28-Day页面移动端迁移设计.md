# Day 页面移动端迁移设计

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:writing-plans` after this design is approved to create the implementation plan.

**Goal:** 将桌面端 `rhythm` 的 Day 执行视图迁移到 `rhythm-mobile`，完成 `Task / DailyPlan / Habit` 三种执行项的统一展示、日期切换、完成状态切换，以及 `Task` 的新建、编辑、删除能力。

**Architecture:** 移动端 Day 页采用 `Expo + React Native + TypeScript` 独立实现，直接对接现有 Supabase 后端。页面通过三路查询获取 `Task / DailyPlan / Habit`，在 feature 层统一转换为 `DayExecutionItem`，再渲染为单列移动端执行流。Day 页只承担“今天执行”职责，不承担 `DailyPlan / Habit` 的规划和编辑职责。

**Tech Stack:** Expo, React Native, TypeScript, Expo Router, Supabase, TanStack Query, Zustand, React Native Testing Library, Jest

---

## 1. 背景与范围

### 1.1 页面定位

`rhythm-mobile` 的 Day 页定位为“今天执行视图”。用户打开页面后，直接看到当天所有需要执行的事项，并能快速完成状态切换。不同数据源在视觉上统一呈现，只通过来源标签区分。

页面需要回答两个问题：

- 今天要做什么。
- 今天完成到哪了。

### 1.2 迁移范围

- 日期切换：支持前一天、今天、后一天。
- 执行项展示：统一展示 `Task / DailyPlan / Habit`。
- 执行项混排：有时间的执行项按开始时间升序混排。
- 无时间事项：进入 `UnscheduledSection`，有内容时默认展开，无内容时隐藏。
- 完成切换：三种数据源均支持在 Day 页切换完成状态。
- Task 管理：`Task` 支持新建、编辑、删除。

### 1.3 非迁移范围

- 番茄钟。
- 日报弹窗。
- 侧边栏抽屉。
- 滑动操作。
- `DailyPlan` 的新建、编辑、删除。
- `Habit` 的新建、编辑、删除。
- 跨模块跳转编辑。
- 复杂时间轴重叠排布。

## 2. 信息架构

Day 页采用单列结构，自上而下分为四层。

### 2.1 顶部日期切换区

显示“昨天 / 今天 / 明天”和当前日期。用户切换日期后，页面重新获取当天的三种数据源。

### 2.2 主执行区

有明确时间的 `Task / DailyPlan / Habit` 都进入主执行区，并按开始时间升序混排。卡片使用统一结构，来源标签展示为“个人任务 / 今日计划 / 日常习惯”。

### 2.3 无时间事项区

没有明确时间的执行项进入 `UnscheduledSection`。该区块有内容时默认展开，无内容时不渲染。

### 2.4 页面级新增入口

页面提供“新建任务”入口，仅用于创建 `Task`。Day 页不提供 `DailyPlan / Habit` 的新建入口。

## 4. 数据架构

### 4.1 查询入口

| 数据源 | 查询职责 | 返回类型 |
|--------|----------|----------|
| Task | 查询指定日期内的个人任务 | `TaskRecord[]` |
| DailyPlan | 查询指定日期的每日计划 | `DailyPlanRecord[]` |
| Habit | 查询指定日期需要执行的习惯及当天完成状态 | `HabitRecord[]` |

移动端现有 `Task` 服务已经存在 `listTasksForDate(date)`。后续实现计划以现有 mobile 命名为准；缺失的 `DailyPlan / Habit` 服务在对应 feature 实现前补齐。

### 4.2 聚合模型

`useDayExecutionItems` 负责执行三路查询，并把原始记录转换为统一的 `DayExecutionItem[]`。

```typescript
type DayExecutionItem = {
  id: string
  source: 'task' | 'daily_plan' | 'habit'
  title: string
  description: string
  startAt: string | null
  endAt: string | null
  startMinutes: number | null
  durationMinutes: number | null
  completed: boolean
  categoryLabel: '个人任务' | '今日计划' | '日常习惯'
  readonly: boolean
  original: TaskRecord | DailyPlanRecord | HabitRecord
}
```

### 4.3 排序与归类

- `startMinutes` 有值的执行项进入主执行区。
- 主执行区按 `startMinutes` 升序排序。
- 同一分钟开始的执行项按来源顺序排序：`DailyPlan`、`Task`、`Habit`。
- `startMinutes` 为空的执行项进入 `UnscheduledSection`。
- 跨小时任务按开始时间所在位置展示，不做高度占比和并列列布局。

### 4.4 时间轴约束

MVP 阶段采用线性时间列表。`ExecutionTimeline` 展示小时刻度和对应卡片，但不实现桌面端复杂重叠排布。多个执行项时间重叠时，按排序规则纵向堆叠。

## 5. 操作边界

| 对象 | 展示 | 完成切换 | 新建 | 编辑 | 删除 |
|------|------|----------|------|------|------|
| `Task` | 支持 | 支持 | 支持 | 支持 | 支持 |
| `DailyPlan` | 支持 | 支持 | 不支持 | 不支持 | 不支持 |
| `Habit` | 支持 | 支持 | 不支持 | 不支持 | 不支持 |

### 5.1 Task 链路

- 点击 `Task` 卡片打开 `TaskEditorSheet`。
- `TaskEditorSheet` 支持编辑标题、开始时间、结束时间、备注、完成状态。
- 新建入口创建 `Task`。
- 编辑态支持删除 `Task`。
- 保存成功后关闭 Sheet 并刷新当天任务。
- 保存失败时保留表单内容并显示错误提示。

### 5.2 DailyPlan / Habit 链路

- 点击完成圆圈直接切换完成状态。
- 点击卡片打开只读详情 Sheet。
- 只读详情展示标题、时间、来源、完成状态。
- Day 页不提供 `DailyPlan / Habit` 的编辑、删除、新建入口。

## 6. 状态与错误处理

### 6.1 服务端数据状态

TanStack Query 管理三种服务端数据：

- `day-tasks`
- `day-daily-plans`
- `day-habits`

每个 query key 都包含日期字符串，格式为 `YYYY-MM-DD`。

### 6.2 本地 UI 状态

Zustand 管理页面级 UI 状态：

- 当前日期。
- `TaskEditorSheet` 打开状态。
- `ExecutionReadonlySheet` 打开状态。
- 当前编辑中的 `Task`。
- 当前查看中的只读执行项。

### 6.3 查询失败

三路查询互不阻塞。任一路失败时：

- 已成功的数据继续渲染。
- 失败来源显示轻量错误提示。
- 页面提供重试入口。

### 6.4 完成切换失败

完成切换使用乐观更新：

- 用户点击后立即更新 UI。
- 服务端成功后保持当前状态。
- 服务端失败后回滚到原状态。
- 回滚时提示“状态同步失败，请重试”。

### 6.5 Task 保存与删除失败

- 保存中禁用提交按钮。
- 保存成功后关闭 Sheet 并刷新当天数据。
- 保存失败后保留表单内容，提示失败原因。
- 删除成功后关闭 Sheet 并刷新当天数据。
- 删除失败后保持 Sheet 打开，提示失败原因。

## 8. 测试策略

### 8.1 聚合层单测

覆盖 `Task / DailyPlan / Habit` 转换为 `DayExecutionItem` 的规则：

- 来源标签正确。
- 完成状态正确。
- 有时间执行项进入主执行区。
- 无时间执行项进入 `UnscheduledSection`。
- 排序规则稳定。

### 8.2 Hook 层测试

覆盖核心数据行为：

- 日期变化后 query key 变化。
- 三路查询成功后输出统一执行列表。
- 单路查询失败时保留其他来源数据。
- 完成切换成功后缓存更新。
- 完成切换失败后状态回滚。

### 8.3 页面层测试

覆盖核心用户路径：

- `DayScreen` 渲染当天标题和新建任务按钮。
- 点击新建任务打开 `TaskEditorSheet`。
- 点击 `Task` 卡片打开编辑 Sheet。
- 点击 `DailyPlan / Habit` 卡片打开只读详情 Sheet。
- 点击完成圆圈触发完成切换。
- 无时间区有内容时显示，无内容时隐藏。

## 9. 自检清单

### 9.1 需求覆盖

| 需求 | 设计结果 |
|------|----------|
| 日期切换 | `DateSwitcher` 管理前一天、今天、后一天 |
| 三源展示 | `useDayExecutionItems` 聚合 `Task / DailyPlan / Habit` |
| 三源混排 | `ExecutionTimeline` 按时间统一展示 |
| 无时间事项 | `UnscheduledSection` 有内容时默认展开 |
| 完成切换 | `useExecutionItemToggle` 按来源分发 |
| Task 新建 | `TaskEditorSheet` 新建模式 |
| Task 编辑 | `TaskEditorSheet` 编辑模式 |
| Task 删除 | `TaskEditorSheet` 编辑态删除 |
| DailyPlan / Habit 边界 | Day 页只展示、只完成切换 |

### 9.2 一致性检查

- 页面定位统一为“今天执行视图”。
- `Task` 是 Day 页唯一支持完整 CRUD 的对象。
- `DailyPlan / Habit` 在 Day 页只展示和切换完成状态。
- 服务端数据交给 TanStack Query。
- 页面 UI 状态交给 Zustand。
- 时间轴 MVP 采用线性列表，不处理复杂重叠排布。
